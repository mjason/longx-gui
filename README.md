# Longx GUI

已重新初始化为最小 NSH TypeScript 原生应用。

当前包含与系统窗口标题栏合并的浏览器式服务器页签、项目切换栏和原生工作区基础布局。系统窗口按钮与页签处于同一行，不再单独显示标题行。

默认连接“本地服务器” `http://127.0.0.1:7788`，从服务端读取真实项目。服务器创建时从统一的彩色线条图标组中随机分配图标，前六项轮廓不重复，在当前窗口内切换时保持不变；各服务器分别记住当前项目。

服务器标签支持关闭。关闭非当前项不切换；关闭当前项优先选右侧，否则选左侧。关闭最后一项保留窗口和“＋”入口。标签分隔线避开选中项及悬停项，关闭按钮有独立悬停反馈。关闭仅移除当前窗口中的本地页签，不删除远端数据。

“＋”可输入名称和地址，新增服务器页签并读取项目列表。连接失败有错误提示及重试入口，不回退到假数据。服务器配置和选择状态目前只保存在当前窗口内，不持久化。

工作区直接使用 `nsh/base` 的原生 `DockArea`，不是普通 View 拼出的固定侧栏。初始左侧 248pt，文件树和会话列表上下停靠；内容、文件、会话、Git 面板都由原生标签组管理，支持拖动标签、拆分分组和拖拽调整尺寸。底部 24pt 状态栏提供面板开关，拖动后的布局不会因切换内容标签被重置。低于 600pt 使用 DockArea 的原生抽屉模式。编辑缓冲和文件树模型独立于面板位置，移动不丢草稿或缓存。主区保留 32pt 标签栏、28pt 上下文栏和平直输入区，输入随多行文字增长并限制最大高度。

文件侧栏直接使用 `nsh/base` 的原生 `Tree`：24pt 行高、虚拟滚动、原位展开/折叠、方向键导航和 Enter / 双击激活文件。子目录按需读取并缓存，空目录与失败状态在树内展示；标题栏搜索按钮展开筛选框，筛选只覆盖已加载内容，保留匹配文件的祖先目录。会话区显示真实会话列表，点击打开会话标签。

会话正文使用原生虚拟 `List` 和 Markdown `TextView`，显示用户文字、流式助手回复及可展开的工具输出、思考摘要和其他活动。先通过 `getThread` 校验会话所属项目并取得 `kernelThreadId`，再订阅 `thread:${kernelThreadId}`；加入/重连接收快照，按 `seq` 去重合并增量事件，历史以 `earlier` 只读请求逐页加载。阅读旧记录时不抢滚动，提供回到最新入口。工具展开状态按记录 ID 保存，不随虚拟列表单元复用而串行；用户图片和助手 Markdown 图片用原生 `Image` 展示，按比例适配阅读列，相对 URL 基于当前服务解析，加载失败有提示，不读取服务端指定的本机路径。用户保留人像图标，不重复显示「你」。审批／工具请求回答及智能体管理仍需在网页端处理。

输入区参考当前 Web 能力，用原生多行 `Input`、`Select`、`Popover`、`Dialog` 和系统文件选择器实现，没有 WebView。Enter 发送／运行时排队，Shift+Enter 换行，组合态不发送；模型选择支持真实供应商分组、搜索、别名及其回退链，档位仅来自所选模型的 `reasoningLevels`，可跟随会话／项目默认。新会话在第一次发送时才 `startThread`；会话侧栏 ＋ 和 `/new` 仅打开输入区。`@` 搜索项目文件和当值会话，保留 Web 的引用序列化和会话成果接收说明；方向键选择，Enter／Tab 插入，Escape 关闭补全。`/compact`、`/init`、`/goal`、`/git`、`/files`、`/settings` 分别接原生操作或现有面板，目标对话框支持目标与可选 Token 预算。

附件支持截图粘贴、系统选文件和拖入：图片作为 `images` 发送，不超过 32 KiB 的受支持文本文件内联，其他文件带自有 CSRF 会话上传到 `/attachments/:projectId`，发送时引用服务器返回路径，规则与 Web 一致。预览、准备／上传失败状态和移除均保留在草稿内。原生沙箱若拒绝直接读取拖入／粘贴的文件路径，会转到系统选择器让用户确认；不会为此授予整个磁盘读取权限，取消选择不会发送。已上传但移除的附件不擅自删除服务端文件。

运行中可以排队或立即插入；队列支持移除、排序和逐项插入，自动发送需收到前一轮终态，并确认当前会话及根会话没有未审阅的 wait-purpose 后台工作（与 Web 相同的五秒检查）。停止后队列暂停，需显式继续；尚无回复／工具输出的本人轮次可撤回恢复原文，否则中断该轮。停止后的无工具副作用轮次也可撤回或继续。服务端待处理消息支持查看、单条／全部插入。插入仅在明确 `not_running` 时回退为普通发送，网络结果不明不擅自再开一轮。

草稿、附件、模型选择和队列按服务器、项目、数据库会话 ID 保留在本窗口内存中，切换或关闭再打开标签不丢失，不写入磁盘。发送捕获作用域；迟到响应、文件选择／上传结果不会清空或进入另一个会话，也不覆盖发送期间新改的文字。服务端确认后才清除对应已发送内容；结果不明时保留并锁住重发，需用户先核对记录。新建、发送、插入、停止等写操作均使用应用自有会话／CSRF，测试不向真实会话发送消息或中断真实轮次。

时间线参考 Web 的内容分组：用户消息与助手正文直接可读，同一轮连续的工具／思考活动收进默认关闭的原生 `Accordion`，摘要显示数量、运行状态和失败数；展开后，再用原生 `Collapsible` 查看单项详情。后台任务和目标续跑通知不再作为用户长消息铺开。分组键随成员记录保持稳定，流式追加和历史前插不会重置已有分组的展开状态；折叠不会删除原始记录或改变历史游标。

展开的工具文本、思考摘要和后台通知使用原生 Markdown `TextView`，支持标题、列表、代码块复制、链接及图片；命令输出、工具参数和未知结构仍按等宽原文显示。单项底部有「收起此项」，分组底部有「收起执行过程」；固定会话顶栏在有展开内容时提供「全部收起」，长过程阅读到中段也能直接关闭，全部收起会同时清除内层展开状态。

助手每轮只显示一次 Longx 品牌身份，正文使用居中的最大 860pt 阅读列、14pt 字号和 24pt 行高；用户消息用轻底色区分，左侧配与助手同尺寸、同轴对齐的中性人像图标，执行过程采用低对比细线。布局适配浅色、深色及窄面板。非运行中的回复尾部提供「复制已加载正文」，仅复制当前已加载的助手正文，不包含工具或思考；相关文件入口仅来自明确的结构化文件变更事件，已删除文件禁用打开，不从自然语言推断文件或验证状态。

文件激活后在标签中使用原生 `Editor` 打开，支持语法高亮、行号、编辑、撤销和保存按钮 / `⌘S`（其他平台 `Ctrl+S`）。文本缓冲按服务器、项目、路径隔离；切换标签、项目或主题不丢本窗口的草稿，未保存标签有圆点，关闭会询问。普通窗口关闭也会阻止未保存草稿被直接丢弃（强制退出/进程终止不保证恢复，草稿不落盘）。二进制文件不提供文本编辑，服务端截断的超大文件只读。

应用菜单的 `Settings…`（`⌘,`，其他桌面平台 `Ctrl+,`）打开原生设置对话框；底栏主题菜单也有「Settings… · 设置」入口。支持编辑器字体、8–40pt 字号、1.2–2.4 倍行高、跟随语言或 2/4/8 列 Tab 宽度，以及自动换行、行号、缩进线、当前行高亮和空白字符显示。字体来自本机，缺失时由系统回退。设置即时应用到已打开的编辑器，字体/字号/行高同时应用到 Git 差异视图，不重建缓冲或重新读取文件。Tab 宽度不转换已有缩进，自动换行不改文件文本。

编辑器偏好通过 NSH Storage 的 `editor.settings.v1` 保存在本机，跨启动恢复，与主题偏好独立；「恢复默认」仅重置编辑器设置。保存顺序串行化，读取与用户修改冲突时保留用户的新值。读取/保存失败时显示提示，保留本窗口已应用的设置并允许重试保存。设置只涉及已接入的 NSH 原生能力，不含自动保存、格式化器或滚动回弹控制。

未保存文件、关闭窗口和 Git 提交确认使用系统 `AlertDialog.show`，按钮顺序、取消与危险操作样式由平台负责。添加服务器表单使用原生 `Dialog`，弹层水平/垂直居中，仍保留原生焦点与取消行为。`AppButton` 只为原生 `Button` 添加 `flex-row items-center justify-center`，统一按钮文字双向居中，不自制按压/键盘/禁用行为。

保存前重新读取磁盘版本，与初始内容不一致则拒绝覆盖；保存后读回核对。服务端尚无版本号/条件写入，因此这不是原子冲突锁，检查和写入之间仍存在竞态。失败或结果不明时保留草稿、不自动重试。重读按钮在有草稿时禁用，需先保存或显式放弃草稿。

底栏 Git 入口打开参考 Zed 组织的侧栏：顶部「变更」/「历史」原生页签，变更或最近 20 次提交独立滚动，底部固定分支信息、多行提交说明、提交按钮和最新提交摘要。Git 打开时暂时隐藏会话工具区，切回文件后恢复，保留原生 Dock 的位置与尺寸。干净仓库显示空状态；“查看差异”打开当前选中的变更文件（未点选时取勾选项或第一个文件）。

点文件打开原生 `DiffView`，通过 `gitFileVersions` 读取 HEAD 与磁盘工作区的完整文件，使用 `oldValue` / `newValue` 和 `expandAll` 展示全部上下文，不折叠未修改代码，也不使用缺少上下文的局部 patch。默认左右对照（左侧 HEAD，右侧磁盘工作区），版本标题垂直居中。工具栏可切换左右／上下、显示增删行数，并提供「打开源文件」进入对应编辑标签，复用已有缓冲与草稿，不重复打开或强制重读；已删除文件会禁用该入口。显示方式在当前窗口的差异标签之间共享，切换不重新请求文件；不包含未保存草稿。字体、字号与行高沿用编辑器设置。

左右对照时，点击任一侧行号会高亮整条对照行，两侧一起亮起；拖动行号选择多行也会联动。高亮由原生 diff 行锚点定位，而非把左右相同行号硬匹配，因此插入／删除导致的错位和另一侧空白占位都能正确对应，并随内容滚动。高亮不占额外行高、不接管文字选择或复制；上下模式保持原生单栏选择，刷新文件版本会清除旧选择。

“全选提交”和勾选框仅选择将要提交的文件，不表示已暂存。填写说明并在系统对话框确认后，才会暂存并提交所选磁盘文件，不推送。切换变更／历史不丢提交说明或选择，提交成功后清空原说明，失败则保留。合并中、所选文件仍有草稿以及重命名/复制/冲突项禁止该提交入口。提交失败可能已影响暂存区，必须刷新核对。当前客户端未接入独立 Stage All、分支差异或 Publish 接口，界面不提供假入口；暂不提供独立暂存、丢弃改动、分支切换、拉取或推送。

字体使用系统 UI 字体栈（含中文回退），文件名以 13pt 常规字重显示，状态栏为 12pt；正文和辅助文字分别使用明确的深色与中灰，不依赖极浅灰文字区分层级。

底栏右侧的主题菜单支持「浅色 / 深色」，默认使用已确认的暖灰浅色配色。切换即时覆盖顶部、工作区、原生 Tree、菜单和弹窗，不重建工作区或重新读取数据；主题偏好跨启动保存，未知主题回退到浅色。旧版主题偏好保持兼容。保存失败不影响当前切换，菜单会提示。

主题定义集中在 `src/theme/themes.ts`，通过 NSH 的 `setTheme` / `setColorScheme` 应用；组件使用语义 token，不直接写颜色。新增主题需提供完整的 `AppTheme` 调色板；新增颜色角色还需在 `nsh.json` 声明以生成 token 类型。当前只支持内置主题，尚未实现外部主题文件导入或跟随系统。

接口契约参照上级服务端 `../longx/priv/schema.graphql`：

- `/gql` 的 `listProjects`：读取项目列表。
- `/gql` 的 `listFiles`、`listThreads`：读取选中项目的根目录和会话摘要；展开目录时单独查询 `listFiles`。
- `readFile` / `writeFile`：打开与保存项目文件，仅允许项目相对路径。
- `gitChanges` / `gitLog` / `gitFileVersions` / `gitCommit`：Git 状态、历史、完整文件差异与按路径提交。
- `getThread`：读取数据库会话 ID 与内核 ID 的映射及所属项目，不混用两种 ID。
- Phoenix `/socket/websocket?vsn=2.0.0`：`project:${projectId}` 的 Git/文件通知，以及 `thread:${kernelThreadId}` 的快照、事件和只读历史请求。Git/文件推送正常连接时停止轮询，断线后才使用兜底检查。

读取使用 GraphQL GET。文件保存和提交使用 POST，先从目标服务主页建立应用自己的会话，携带刚签发的 cookie/CSRF token；不读取浏览器 cookie、不持久化或记录会话凭据、不绕过认证/证书。无法建立会话则阻止写入。普通读取超时 10–15 秒，提交操作超时 90 秒；操作结果不明时绝不自动重试。切换项目的读请求有取消或作用域隔离，旧结果不会覆盖新项目。没有 WebView，也不修改服务端代码。


组件通过响应式读取函数和事件回调协作；跨组件状态由 `createWorkspaceState()` 创建，不使用全局单例。悬停、表单输入等临时状态保留在对应组件内。

工作区标签的拖动、分组与缩放由原生 DockArea 管理，`contentTabs.ts` 保留打开内容及激活状态，`nativeDock.ts` 只合并新增/关闭项并保留原生布局。原来的 `WorkspaceTabs.tsx` 已移除。标签在窄分组内可收缩，关闭按钮不被长标题挤出。切换服务器或项目会清空内容标签，但文本草稿仍按原作用域保存在内存，切回原项目重新打开文件可继续。布局暂不跨启动持久化。

## 开发质量检查

应用仍由 NSH 构建和运行，不依赖 React 或 Node 运行时。`package.json` 仅管理开发工具：
固定版本的 Biome 同时负责 TS/TSX/JSON 格式化、import 整理和静态检查，NSH 负责类型检查、
应用测试和原生构建。依赖版本由 `package-lock.json` 锁定。

```sh
npm ci --ignore-scripts
npm run format        # 统一格式（2 空格、双引号、100 列、LF）
npm run format:check  # 只检查格式
npm run lint          # 静态检查，警告也会失败
npm run check         # 格式 + lint + import 顺序，只检查
npm run check:fix     # 格式及安全自动修复，不启用 --unsafe
npm run typecheck     # nsh check
npm test              # nsh test
npm run build         # nsh build
npm run quality       # check → typecheck → test → build，任一步失败即停止
```

`nsh` 应在 PATH 中；本机使用独立安装目录时，可设置 `NSH_BIN` 为其可执行文件路径，
不需要全局安装或把个人安装路径写进仓库：

```sh
NSH_BIN=/absolute/path/to/nsh npm run quality
```

Biome 遵循 `.gitignore`，并明确排除 `.nsh`、`.tools`、`.longx`、`target`、
`node_modules` 和资源目录，不整理生成代码或下载的框架源码。`If` / `Each` 是 NSH 编译器提供的全局控制流，
不是未声明的 React 组件。不启用 React 专用规则；允许非空断言，以适配已判空但类型系统无法跨响应式读取保持收窄的代码，
其余推荐规则保持启用。`.editorconfig` 与格式化器的缩进、编码和换行保持一致。

建议编辑器安装 Biome 扩展并选择工作区版本。工具不会安装 Git hooks、修改全局配置或自动提交代码。
